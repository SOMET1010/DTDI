# PASS Academy — Doctrine UX inclusive V1.3

## Promesse
PASS Academy doit pouvoir être utilisé par une personne qui ne sait lire aucun mot. Le texte améliore l'expérience des lecteurs mais ne doit jamais être nécessaire pour comprendre, choisir, agir ou terminer une histoire.

## Formule produit
Illustration cartoon + voix SUTA + geste simple + histoire + texte facultatif.

## Règles non négociables
1. Un écran = une intention = une action principale.
2. Toute instruction essentielle existe en audio.
3. Toute décision essentielle possède une représentation visuelle compréhensible sans texte.
4. Maximum trois choix simultanés ; deux sont préférables.
5. SUTA parle avec des phrases courtes et un vocabulaire quotidien.
6. Pas de menu profond : accueil, SUTA, progression.
7. Les personnages et scènes sont récurrents pour créer de la familiarité.
8. Une erreur n'est jamais punitive : SUTA reformule et invite à réessayer.
9. Les apprentissages restent séparés de l'éligibilité PASS.
10. Le fonctionnement essentiel est offline-first.

## Grammaire d'une histoire
1. Je vois le personnage et sa situation.
2. SUTA raconte oralement le problème.
3. Je touche une image pour entendre ce qu'elle représente.
4. Je choisis/je fais une action.
5. Je vois immédiatement la conséquence.
6. SUTA explique la règle utile en une phrase.
7. Une scène de réussite clôt l'histoire.

## Direction artistique
Cartoon 2D premium, chaleureux et adulte. Personnages ivoiriens crédibles, expressions lisibles, formes rondes, décors simples mais locaux, objets numériques très reconnaissables. Palette ANSUT/PASS avec accents chauds. Les emoji ne sont que des placeholders de développement et doivent disparaître de la version de production.

## Test Zéro Lecture
Pour chaque histoire, masquer tous les textes et confier le téléphone à un participant. Sans aide humaine, il doit pouvoir :
- démarrer ;
- identifier le personnage et la situation ;
- écouter SUTA ;
- comprendre qu'une décision est attendue ;
- écouter la signification des choix ;
- choisir ;
- comprendre réussite/erreur ;
- terminer et revenir à l'accueil.
Un échec sur une de ces étapes est un défaut UX bloquant.

## Mesure d'impact
Chaque compétence doit avoir trois mesures séparées de l'éligibilité :
- avant : sait-il réaliser l'action sans aide ?
- juste après : peut-il la réaliser seul ?
- rétention : peut-il encore la réaliser plus tard ?
Les métriques produit doivent privilégier la réussite réelle de l'action plutôt que le temps passé dans l'application.

## Critères de recette V1.3
- parcours complet réalisable en mode zéro lecture ;
- audio rejouable partout où il porte une instruction ;
- aucune action critique dépend d'un libellé texte ;
- cibles tactiles grandes et espacées ;
- reprise de progression locale ;
- histoire e-Justice incluse ;
- aucune prétention de contenu officiel GSMA sans validation de source/droits ;
- aucune illustration emoji dans la cible graphique finale.
