# Prototype Tata Nanti / première photo — Assets graphiques requis

Branche `pass-academy-tata-nanti-prototype`, créée depuis `pass-academy-v03`
(gelée pour la recette terrain — non modifiée). Objet : valider une nouvelle
grammaire zéro lecture pour une histoire à la fois (« phone-photo » — Tata
Nanti) avec de vraies images fournies par l'équipe design, avant de
l'appliquer aux 13 autres histoires du catalogue.

Depuis ce prototype, aucune illustration de « phone-photo » n'est plus
dessinée à la main en SVG. Le contenu narratif (voix, choix, logique) est
strictement inchangé — seule l'illustration est concernée. En attendant les
assets réels, l'app affiche un repère neutre « ASSET_REQUIRED » à la place
de chaque illustration manquante.

**7 assets à fournir** (5 scènes + 2 cartes de choix). Ce nombre est vérifié
automatiquement par `tests/tata-nanti-prototype-assets-pending.test.js`.

Personnage : Tata Nanti est déjà illustrée dans l'app (`art/cartoon-v13.js`,
buste réutilisé sur toutes ses histoires). **Aucun nouveau buste n'est
requis.**

Gabarits déjà en usage dans l'app (à respecter pour l'intégration) :
- Illustration de scène : 320×180, arrondi 22px à l'affichage, conteneur
  190px de haut.
- Carte de choix : 160×110, arrondi 18px, conteneur ≥135px de haut.

## Comment livrer un asset

Remplacer l'appel `window.assetRequired('<id>', '<description>')`
correspondant — dans `app/src/main/assets/art/scenes-v13.js` (illustrations
de scène) ou `app/src/main/assets/content/narrative-pilots-v13.js` (cartes
de choix) — par :
- `'<svg viewBox="0 0 320 180">...</svg>'` (ou `"0 0 160 110"` pour une carte
  de choix) si l'asset est livré en SVG déjà validé ;
- `'<img src="art/tata-nanti/<fichier>.svg" alt="...">'` si l'asset est
  livré comme fichier séparé (à placer sous
  `app/src/main/assets/art/tata-nanti/`).

La mise à l'échelle responsive (proportions préservées, `object-fit:contain`)
est déjà gérée par `css/app.css` — aucune modification CSS nécessaire pour
un asset qui respecte les gabarits ci-dessus. Les transitions déjà en place
(`sceneIn`, `.pilot .dots`, `motionClass` dans `js/renderers.js` pour
"phone-photo") s'appliqueront automatiquement.

**Rappel de neutralité (C1.9d, toujours en vigueur)** : le fond visuel
d'une carte de choix ne doit jamais varier selon `good`/`bad` avant
sélection — `tests/choice-card-neutrality.test.js` le vérifie
automatiquement dès qu'un asset réel remplace un repère ASSET_REQUIRED.

## Ce qui n'est pas dans ce lot

- Aucun changement de contenu narratif, de voix ou de logique de choix pour
  "phone-photo" — uniquement l'illustration.
- Aucune 5ᵉ histoire, aucun packaging, aucun merge vers `pass-academy-v03`
  (toujours gelée pour la recette terrain).
- Si la validation de ce prototype conduit à changer la *structure* même
  d'une scène (nombre d'étapes, type d'interaction) au-delà de
  l'illustration, ce sera un lot séparé et explicitement demandé — pas une
  extension silencieuse de celui-ci.
