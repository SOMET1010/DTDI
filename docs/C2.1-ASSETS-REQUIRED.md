# C2.1 — Assets graphiques requis (Famille B)

Manifeste des illustrations à fournir pour les 4 nouvelles histoires Famille B
(`docs/pass-academy-gsma-mistt-alignment-c2.0.md`, section 6). Depuis C2.1,
aucune de ces illustrations n'est dessinée à la main en SVG par moi : le
code les intègre uniquement une fois livrées (voir « Comment livrer un
asset » ci-dessous). En attendant, l'app affiche un repère neutre
« ASSET_REQUIRED » à la place de chaque illustration manquante — jamais une
interprétation graphique de mon cru, jamais un indice de couleur good/bad.

24 assets à fournir au total (4 histoires × (3 scènes + 3 cartes de choix)).
Ce nombre est vérifié automatiquement par `tests/famille-b-assets-pending.test.js`
(`PASS_ASSET_REQUIRED_LIST.length === 24`) : si ce document est mis à jour
(assets livrés, retirés, ajoutés), le test doit être mis à jour en
conséquence.

Personnages : les 4 histoires réutilisent des personnages déjà illustrés
dans l'app (Yao, Konan, Issa, Mariam — `art/cartoon-v13.js`). **Aucun
nouveau buste de personnage n'est requis.**

Gabarits déjà en usage dans l'app (à respecter pour l'intégration) :
- Illustration de scène : 320×180 (format `art/scenes-v13.js`), arrondi 22px
  à l'affichage (`.sceneArt{border-radius:22px}`), conteneur 190px de haut.
- Carte de choix : 160×110, arrondi 18px, conteneur ≥135px de haut/large,
  grille 2 colonnes (`.pilotChoice{grid-template-columns:1fr 1fr}` — les
  scènes de choix Famille B ont 3 choix chacune, donc 3 cartes par scène,
  la 3ᵉ passe en 2ᵉ ligne).

## Comment livrer un asset

Remplacer l'appel `window.assetRequired('<id>', '<description>')` correspondant,
dans `app/src/main/assets/art/scenes-famille-b.js` (illustrations de scène)
ou `app/src/main/assets/content/famille-b-pilots.js` (cartes de choix), par
soit :
- `'<svg viewBox="0 0 320 180">...</svg>'` (ou `"0 0 160 110"` pour une carte
  de choix) si l'asset est livré en SVG déjà validé ;
- `'<img src="art/famille-b/<fichier>.svg" alt="...">'` si l'asset est livré
  comme fichier séparé (à placer sous `app/src/main/assets/art/famille-b/`).

Dans les deux cas, la mise à l'échelle responsive (proportions préservées,
`object-fit:contain`) est déjà gérée par `css/app.css` — aucune modification
CSS nécessaire pour un asset qui respecte les gabarits ci-dessus.

**Rappel de neutralité (C1.9d, toujours en vigueur)** : le fond visuel d'une
carte de choix ne doit jamais varier selon `good`/`bad` avant sélection —
`tests/choice-card-neutrality.test.js` le vérifie automatiquement dès qu'un
asset réel remplace un repère ASSET_REQUIRED.

## Ce qui n'attend pas d'asset

Les animations légères de transition entre scènes (`sceneIn`, `.pilot .dots`)
et le repère de chargement `.assetRequired` lui-même sont déjà en place et
s'appliqueront automatiquement aux assets une fois livrés — aucune
intervention supplémentaire nécessaire côté moteur pour ces 4 histoires.
